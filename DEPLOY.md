# Deploying SevaSetu

The backend runs as **one** Node service on Render (`node mono.js`: gateway + core + reflect + bridge in one
process, one URL), the web app on Vercel, and the data in MongoDB Atlas. AI and speech keys are optional: without
them every AI job answers with its fallback. Nothing in the repo holds a secret; `.env.example` is the template.

## 1. MongoDB Atlas (5 minutes)

1. atlas.mongodb.com → create a free (M0) cluster → Database Access: add a user with a password →
   Network Access: allow `0.0.0.0/0` (Render's IPs change).
2. Connect → Drivers → copy the string. Put a database name before the `?`, e.g.
   `mongodb+srv://USER:PASSWORD@cluster0.xxxxx.mongodb.net/sevasetu?retryWrites=true&w=majority`.
3. You do not need to seed by hand: with `SEED_ON_START=true` (set in the Blueprint) the service fills an
   **empty** database with the demo data on its first boot, and never touches a database that already has users.
   To reseed from your laptop instead: `MONGO_URI="…/sevasetu" npm run seed:mono`.

## 2. Render: the backend (one service)

render.com → New → **Blueprint** → pick this repo → it reads [render.yaml](render.yaml) and creates `sevasetu`.
Fill in what it asks for:

| Variable | Value |
|---|---|
| `MONGO_URI` | the Atlas string from step 1 |
| `WEB_ORIGIN` | leave empty for now; set it to the Vercel URL after step 3 |
| `LLM_API_KEY` | Groq key (optional) |
| `BHASHINI_USER_ID`, `BHASHINI_ULCA_API_KEY`, `BHASHINI_INFERENCE_API_KEY` | from your Bhashini profile (optional) |

`JWT_SECRET` is generated by Render. When the deploy finishes, open `https://sevasetu-XXXX.onrender.com/health/all`:
it must say `{"core":true,"reflect":true,"bridge":true}`. That URL is the gateway.

## 3. Vercel: the web app

Import the repo → root directory `apps/web` → environment variable `VITE_API_URL` = the Render URL → deploy.
[vercel.json](apps/web/vercel.json) sends every path to the app, so refreshing `/my-seva` works.
Then go back to Render and set `WEB_ORIGIN` to the Vercel URL (it redeploys by itself).

Or from the terminal, with the Vercel CLI logged in:
`cd apps/web && vercel --prod -e VITE_API_URL=https://sevasetu-XXXX.onrender.com`

## 4. Check it

```bash
GW=https://sevasetu-XXXX.onrender.com node scripts/api-test.js
WEB=https://your-app.vercel.app GW=https://sevasetu-XXXX.onrender.com node scripts/ui-test.js   # needs Google Chrome
```

Render's free service sleeps after 15 minutes idle: open `/health/all` two minutes before a demo to wake it.

## Four services instead of one

If you ever need to scale the parts apart, each has its own `server.js` (`services/<name>/src/server.js`) and its
own variables (`CORE_MONGO_URI` / `REFLECT_MONGO_URI`, `CORE_URL` / `REFLECT_URL` / `BRIDGE_URL` for the gateway,
the bridge keys). The gateway proxies by path; `mono.js` is the same four apps mounted in one process.

## Showing Swami Vivekananda's words

Quotes are hidden until a person checks each one in a printed volume of the *Complete Works*. To show one, set
`"verified": true` and its `"page"` in [seed/wisdom.json](seed/wisdom.json), then reseed Atlas from your laptop
(`MONGO_URI="…/sevasetu" npm run seed:mono`) and redeploy (the bridge reads the same file for the Teaching Finder).
